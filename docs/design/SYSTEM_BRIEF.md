# PS-клуб: описание системы для дизайнера

Документ для дизайнера (человека или ИИ). Описывает продукт, людей, экраны, состояния и
ограничения. Технические подробности — в `docs/SPEC.md`.

---

## 1. Что это

Веб-приложение для кассы небольшого клуба PlayStation в Бишкеке: 5–6 консолей PS5,
к каждой подключён телевизор. Заменяет бумажную тетрадь, в которой сейчас ведут учёт:
кто за какой консолью, сколько времени осталось, сколько заплатили, что взяли в баре,
сколько денег в кассе в конце дня.

Фазы:

1. **Сейчас.** Таймеры на экране, касса, бар, рабочий день, сводка в Телеграм.
   Телевизоры оператор выключает руками.
2. **Потом.** Умные розетки сами обесточивают ТВ, когда оплаченное время кончилось.
3. **Ещё позже.** Аналитика: выручка, загрузка по часам, бар.

Главная причина писать своё — не платить ежемесячную подписку за каждое устройство в
готовых системах вроде LANGAME.

## 2. Кто пользуется и в каких условиях

| | |
|---|---|
| **Оператор** | Владелец клуба. Почти всегда сам за кассой. Иногда на пару часов его подменяет другой человек под тем же логином. Ролей и сотрудников нет |
| **Где** | Обычный ПК с Windows на стойке кассы, монитор 1366–1920 px. Иногда телефон |
| **Когда** | Весь рабочий день, примерно 10:00–05:00. Экран открыт 19 часов подряд, большая часть работы приходится на вечер и ночь |
| **Обстановка** | Полутёмный зал, шум, гости подходят к стойке. Оператор смотрит на экран мельком, часто с расстояния 1–2 метров, между делами |
| **Вне клуба** | Владелец получает сводки в Телеграм. Если система развёрнута в интернете, может открыть веб с телефона |

Что из этого следует для интерфейса:

- **Зал считывается за секунду.** Какая консоль свободна, у какой скоро конец, где
  переигрыш — видно с расстояния, без чтения мелкого текста.
- **Одно-два нажатия** на частые действия: начать, продлить, принять оплату.
- **Ошибки дорогие.** Это деньги. Действия, которые нельзя отменить (завершить сессию,
  закрыть день), требуют подтверждения. Ручные изменения попадают в журнал.
- **Экран долго светит в темноте.** Не должен слепить ночью.
- **Звук** сопровождает предупреждения: за 5 минут до конца и когда время вышло.

## 3. Словарь

Термины в интерфейсе должны быть ровно такими.

| Термин | Значение |
|---|---|
| **Консоль** | Место в зале: PS5 + телевизор. Называются «PS 1», «PS 2»… |
| **Сессия** | Визит гостей к одной консоли от старта до завершения. Состоит из отрезков и счёта |
| **Отрезок** | Кусок времени внутри сессии. Каждое продление — новый отрезок |
| **Пакет** | Отрезок фиксированной длины и цены: 1, 3 или 5 часов. Есть время окончания |
| **Открытое время** | Отрезок без конца, оплата поминутно при уходе. Сумма растёт на глазах |
| **Выбор игры** | Первые 3 минуты после старта. Бесплатны. Если гости ушли за это время — сессию отменяют без оплаты. Бывает только при старте, не при продлении |
| **Переигрыш** | Время пакета вышло, а гости ещё играют. Показывается как «+07:12» |
| **Платная / бесплатная / служебная** | Типы сессии. Бесплатная — друзья владельца, обязательна причина. Служебная — обновления, проверка геймпадов, ТВ для себя |
| **Счёт** | Время + заказы из бара. Гасится платежами в любой момент, частями, разными способами |
| **Способ оплаты** | Наличные, QR (MBank, O!Dengi), перевод по номеру. Карточного терминала нет |
| **Чек без игры** | Продажа из бара без консоли: гость просто купил воду |
| **Рабочий день** | Открывается и закрывается вручную. Всё между открытием и закрытием — один день в отчётах, даже если перешло через полночь |
| **Касса** | Наличные на начало дня + наличные платежи. Безнал всегда отдельно |

## 4. Экраны

### 4.1 Вход

Один логин и пароль на весь клуб. Простая форма.

### 4.2 Открытие дня

Если день не открыт, вместо зала — предложение открыть: «День не открыт. Открыть?» и
поле «Наличные на начало». Одно действие, не блокировка.

### 4.3 Зал — главный экран

Здесь проходит весь рабочий день. Карточка на каждую консоль (5–6 штук, в будущем
появятся VIP-комнаты — отдельная зона со своими консолями и ценами).

**Состояния карточки** — главное, что должен решить дизайн:

| Состояние | Что показывает | Действия |
|---|---|---|
| Свободна | «Свободна», когда закончилась последняя сессия | Начать сессию |
| Выбор игры | Как пакет или открытое время + обратный отсчёт 3 минут | Отменить без оплаты, остальные действия сессии |
| Идёт пакет | Остаток крупно (`2:41:07`), до скольки, прогресс, счёт / оплачено / к оплате | Продлить, бар, оплата, стоп |
| Скоро конец | Последние 5 минут пакета. Подсветка + звук | Продлить — главное действие |
| Переигрыш | Время вышло: «+07:12» красным, звук. В фазе 1 — подсказка «Выключите ТВ на PS 3» | Продлить, завершить |
| Открытое время | Сколько прошло (`52:30`), текущая сумма растёт в реальном времени | Бар, рассчитать и завершить |
| Бесплатная | Сколько прошло, причина. Денег нет | Завершить, перевести в платную |
| Служебная | Сколько прошло, пометка «служебная» | Завершить |
| Обслуживание | Консоль выключена из работы | — |
| Не оплачено | Модификатор к любому состоянию: есть долг по счёту | Принять оплату |

Таймеры тикают каждую секунду. Отсчёт идёт на сервере, закрытие вкладки ни на что не
влияет.

**На экране зала также:**

- статус дня: открыт с какого времени, сколько идёт;
- текущее время (Бишкек);
- **чеки без игры** — продажи бара без консоли, пока не оплачены;
- действия: продажа без игры, история дней, закрыть день;
- желательно — **касса дня прямо на экране**: наличные в кассе, QR, перевод отдельно,
  количество сессий, бар; лента событий дня (кто, когда, сколько) — цифровая замена
  тетради.

### 4.4 Старт сессии

Открывается с карточки свободной консоли.

- Тип: платная (по умолчанию) / бесплатная / служебная.
- Платная — выбор тарифа: 1 ч, 3 ч, 5 ч, открытое время. У каждого — цена и до
  скольки продлится (с учётом 3 минут на выбор игры).
- Бесплатная — поле «Причина», обязательно. Можно быстрые варианты.
- **Предупреждение**, если пакет закончится после планового закрытия (05:00):
  «Пакет закончится в 05:43 — после планового закрытия». Не запрет, решает человек.
- Кнопка с итогом: «Начать на PS 5 · 400 сом».

Пакет обычно оплачивают сразу, но это не обязательно — оплатить можно позже.

### 4.5 Сессия (детали)

Открывается кликом по занятой карточке. Боковая панель или отдельный экран.

- **Отрезки** — лента: выбор игры → пакет 3 ч → продление 1 ч → открытое время…
  С временем начала и суммой.
- **Счёт**: время, бар, оплачено, к оплате.
- **Оплата**: сумма (по умолчанию — весь остаток), способ: наличные / QR / перевод.
  Можно частями: 200 наличными + 190 по QR.
- **Продление**: те же тарифы. Переход на открытое время во время пакета начинается
  **с конца пакета**, а не с момента нажатия — это надо показать («с 23:40, поминутно»).
- **Бар**: добавить товары на счёт.
- Завершить сессию. Если есть долг — сразу переход к оплате.

### 4.6 Бар

Каталог небольшой: напитки, сэндвичи, снеки (10–30 позиций). Название и цена.
Добавление в счёт сессии или в чек без игры, количество ±. Склада и остатков нет.

### 4.7 Закрытие дня

Это последовательность шагов:

1. **Завершить активные сессии** — список с долгами, у каждой «Завершить». Пока есть
   активные, день не закрыть.
2. **Пересчитать наличные** — система показывает, сколько должно быть; оператор вводит,
   сколько насчитал; расхождение подсвечивается.
3. **Безнал** — QR и переводы отдельными строками, их сверяют по банковскому приложению.
4. Закрыть. Сводка уходит владельцу в Телеграм.

### 4.8 История дней

Список закрытых дней: дата открытия и закрытия, выручка наличными / QR / переводом,
расхождение, сессии, часы, бар. Открыть день — подробности.

### 4.9 Фаза 2 (заложить место, делать не сразу)

- Индикатор связи с «агентом» (служба, управляющая розетками) — в шапке.
- На карточке: питание ТВ вкл/выкл, ошибка розетки.
- Кнопка «Включить ТВ без оплаты» — создаёт служебную сессию.
- Сессия «ручное включение», созданная автоматически, если кто-то включил ТВ кнопкой
  на розетке.

### 4.10 Фаза 3 — аналитика (по желанию)

Выручка по дням и неделям по способам оплаты, загрузка по часам и дням недели,
средний чек, бар, бесплатные часы отдельно. Возможно, хватит таблиц.

### 4.11 Настройки

Сейчас — стандартная админка (SQLAdmin): тарифы, зоны, консоли, товары, время на выбор
игры, часы работы. Отдельный дизайн не нужен.

## 5. Правила, которые влияют на интерфейс

- **Деньги** — целые сомы, без копеек. Формат: `1 240 сом`. Разделитель тысяч — пробел.
- **Время** — 24 часа, часовой пояс Бишкека. Остаток: `2:41:07`, меньше часа — `41:07`.
  Цифры моноширинные, чтобы таймер не прыгал.
- **Наличные и безнал всегда раздельно.** Нигде не складывать их в одну «выручку» без
  разбивки.
- **Остаток времени важнее всего остального на карточке.**
- **Ручные действия** (бесплатная сессия, отмена, досрочный стоп, правка) пишутся в
  журнал — интерфейс может честно об этом говорить.
- **Цены могут меняться**, но старые сессии сохраняют цену на момент продажи.
- Цвет — не единственный носитель статуса: дублировать формой, иконкой или текстом.

## 6. Пример данных

Ночь, 00:40, день открыт в 10:02.

| Консоль | Состояние | Детали |
|---|---|---|
| PS 1 | Пакет 3 ч, выбор игры | осталось 3:01:44, до 03:41, оплачено 400 |
| PS 2 | Скоро конец | 03:44, пакет 1 ч, бар 240 не оплачен |
| PS 3 | Переигрыш | +06:15, пакет 3 ч + продление 1 ч, оплачено 550 |
| PS 4 | Открытое время | идёт 52:33, 160 сом/ч, время 132 + бар 120 = 252 к оплате |
| PS 5 | Свободна | последняя сессия закончилась в 23:57 |
| PS 6 | Бесплатная | 27:28, «друзья владельца» |

Касса дня: на начало 2 000, наличные в кассе 5 830, QR 2 150, перевод 600.
23 сессии, 31 ч 40 мин игры, бар 690. Чек без игры №214: вода 0,5 × 2, сникерс — 150.

Тарифы (цены примерные, ещё уточняются): 1 ч — 150, 3 ч — 400, 5 ч — 600,
открытое время — 160 сом/ч.

## 7. Технические рамки

- React + Tailwind + shadcn/ui (Radix). Дизайн должен ложиться на эти компоненты:
  диалоги, листы (sheet), сегментные переключатели, поля, кнопки.
- Весь текст интерфейса — на русском. Шрифты — **обязательно с кириллицей**.
- Ширины: 1366–1920 (основная), планшет, телефон 375.
- Тёмная тема — основная (ночь, полутёмный зал). Светлая — желательна.
- Видимый фокус с клавиатуры, никаких действий только по наведению, учёт
  `prefers-reduced-motion`.

## 8. Чего НЕ нужно

В референсах (LANGAME и аналоги) это есть, но нам не нужно — не рисовать:

- бронирование, приложение для гостей;
- аккаунты гостей, бонусы, скидки, уровни, рассылки;
- сотрудники, роли, смены, зарплаты;
- склад, инвентаризация, закупки;
- магазин игр, игровые аккаунты, контроль процессов;
- фискальная касса;
- боковое меню на десяток разделов. Разделов всего три-четыре: зал, история дней,
  (позже) аналитика, настройки.

## 9. Референс: LANGAME

Коммерческая система для компьютерных клубов, 1500+ клубов. Её экраны у нас есть только
на одном скриншоте: светлые карточки на сером фоне, тёмное боковое меню, красный
акцент, графики посещаемости, KPI-плитки «+20% с прошлым периодом».

Что полезно взять:

- у руководителя есть вкладка, где видно, какие устройства заняты, кем и через сколько
  освободятся — это наш зал;
- касса управляющего за период, логи всех действий;
- сводки по сменам в Телеграм.

Чего избегать:

- **Зал — не дашборд.** У LANGAME главный экран — аналитика, а оператор живёт в
  отдельной программе. У нас оператор и владелец — один человек, и главный экран — зал.
- В отзывах о LANGAME пишут: «не хватает наглядного отображения компов сеткой».
  Наглядная сетка консолей — наш главный экран.
- Общий SaaS-вид «сайдбар + KPI-плитки + графики» не подходит — это не отчёт, а пульт.
