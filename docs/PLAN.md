# PS-клуб: план разработки

Подробности каждого решения — в `SPEC.md`. Открытые вопросы — в `OWNER_QUESTIONS.md`.

## Принципы порядка

1. **Сначала замена тетради.** Система полезна без розеток; автоматика — вторая фаза.
2. **Как можно раньше — в реальный клуб.** Настоящие сценарии не придумать за столом.
3. **Аналитика последней.** Графики по пустой базе бессмысленны.
4. **Решение «локальный или гибрид» не блокирует разработку.** Код один, меняется деплой. Нужно к этапу 7.

Каждый этап заканчивается проверяемым результатом. Следующий не начинается, пока критерий не выполнен.

## Фаза 1 — замена тетради

### 1. Каркас репозитория

- Монорепо: `core/`, `web/`, `bot/`, позже `agent/`
- Docker Compose для разработки: Postgres, api, worker, bot
- Alembic, линтеры (ruff, eslint), pytest, vitest
- Генерация TypeScript-типов из OpenAPI-схемы
- `.env.example`, README с запуском

**Готово, когда:** `docker compose up` поднимает пустое ядро с БД, миграции проходят, фронт открывается и получает ответ от API.

### 2. Доменное ядро

- Модели: зоны, консоли, тарифы, рабочие дни, сессии, отрезки, товары, заказы, платежи, журнал, настройки
- Доменная логика **без I/O**: расчёт стоимости, отрезки, 3 минуты на выбор игры, переход на открытое время во время пакета, округление до сома
- Сервисы: старт, продление, стоп, отмена, оплата; бесплатные и служебные сессии
- `PlugDriver` + ручной драйвер
- API и SQLAdmin для настроек

**Готово, когда:** доменная логика покрыта тестами без БД; через API проходит полный цикл: старт пакета → продление открытым временем → стоп → оплата частями.

### 3. Экран зала

- Карточки консолей, живые таймеры через WebSocket
- Предупреждение за 5 минут и в конце: подсветка и звук
- Переигрыш
- Старт, продление, стоп, диалог оплаты (наличные / QR / перевод, частями)
- Авторизация: один логин на клуб
- Вёрстка, пригодная для телефона

**Готово, когда:** сессию от старта до оплаты можно провести целиком в браузере, не трогая API руками; вкладку можно закрыть и открыть — таймеры не сбились.

### 4. Бар

- Каталог в SQLAdmin
- Добавление товаров на счёт сессии
- Продажа без игры отдельным чеком

**Готово, когда:** сэндвич добавляется на счёт и оплачивается вместе со временем; воду можно продать без консоли.

### 5. Рабочий день

- Открытие с наличными на начало
- Закрытие: активные сессии, пересчёт, безнал отдельно
- «День не открыт. Открыть?» при старте сессии
- Предупреждение о пакете, заканчивающемся после планового закрытия

**Готово, когда:** день открывается и закрывается; ожидаемые наличные сходятся с суммой платежей наличными плюс остаток на начало.

### 6. Телеграм-бот

- Доступ только для `chat_id` владельца
- Сводка при закрытии дня
- Напоминание о незакрытом дне (через worker)
- Команда «что сейчас в зале»

**Готово, когда:** владелец получает сводку на телефон после закрытия дня; бот игнорирует всех остальных.

### 7. Деплой и пилот

- **Нужно решение владельца:** локальный вариант или гибрид
- Деплой, HTTPS (для гибрида), nginx
- Бэкапы с первого дня
- Страница `/health`
- Тетрадь убирается; неделя реальной работы

**Готово, когда:** неделя работы без потерянных денег и без ручных правок в базе. Всё, что всплыло, записано и разобрано.

## Фаза 2 — автоматика

### 8. Агент и протокол

- Отдельный пакет `agent/`
- WebSocket-клиент: снимок желаемого состояния, отчёт о фактическом, пинги, переподключение
- Кэш снимка на диск, исполнение дедлайнов без связи с ядром
- Драйвер под выбранную розетку, фейковый драйвер для тестов
- На стороне ядра: WebSocket для агента, `plug_events`, служебная сессия при ручном включении
- nginx: настройки WebSocket (см. `SPEC.md`, раздел 6)

**Готово, когда:** с фейковым драйвером — обрыв связи посреди сессии не мешает ТВ «выключиться» вовремя; после восстановления связи состояние синхронизируется само.

### 9. Проверка железа

- Одна розетка, один ТВ, как в клубе
- Проверить: включается ли TCL сам при подаче питания, на какой вход, сколько грузится
- Проверить локальное управление: вкл, выкл, состояние, мощность
- Если ТВ не включается сам — настройки питания или HDMI-CEC; если не помогает — пересмотреть подход

**Готово, когда:** агент на реальной розетке включает и выключает ТВ по сессиям, и после подачи питания на экране сразу приставка.

### 10. Розетки на всех консолях

- Закупка остальных розеток
- Статические IP на роутере
- Гостевой WiFi, если гости сидят в одной сети с розетками
- Алерты в боте: агент пропал, розетка не ответила, ТВ включён без сессии
- Кнопка «включить ТВ без оплаты» в интерфейсе и боте

**Готово, когда:** неделя работы всех консолей в автоматическом режиме без ручного вмешательства.

## Фаза 3

### 11. Аналитика

- Выручка по дням и неделям, по способам оплаты
- Загрузка по часам и дням недели
- Средний чек, продажи бара, бесплатные часы
- Выбор библиотеки графиков — или таблицы, если владельцу их хватит

**Готово, когда:** владелец отвечает на вопрос «когда клуб пустой и сколько мы заработали за месяц» без калькулятора.

## Когда нужны ответы владельца

| Этап | Что нужно |
|---|---|
| 2 | Цены пакетов и часовая ставка открытого времени |
| 7 | Локальный вариант или гибрид; ПК кассы |
| 9 | Модели ТВ и результат теста телевизора |
| 10 | Гостевой WiFi |
| вне MVP | VIP-комнаты, фискализация, учёт остатков, учёт клиентов |

Тест телевизора (выдернуть вилку включённого ТВ и вставить обратно) не требует кода. Лучше сделать его как можно раньше: если ТВ не включается сам, фаза 2 может измениться.
